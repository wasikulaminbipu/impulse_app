# Code Generation Pipeline & Build Runner

This project relies on multiple code generation tools simultaneously:
- **`riverpod_generator`** -> `.g.dart` (Riverpod 3.x / Annotation 4.x)
- **`drift_dev`** -> `.g.dart` (Drift 2.20+ schema & DAOs)
- **`freezed`** -> `.freezed.dart` (Freezed 3.x immutable models & unions)
- **`json_serializable`** -> `.g.dart` (JSON parsing & serialization)

---

## 1. Standard Generation Commands

Always use `dart run` (Dart 3 standard) instead of legacy `flutter pub run`.

### Full Project Generation
Always run with `--delete-conflicting-outputs` (or `-d`) to clean stale artifacts:
```bash
dart run build_runner build --delete-conflicting-outputs
```

### Continuous Watch Mode (Development)
```bash
dart run build_runner watch --delete-conflicting-outputs
```

### Targeted Single-Builder / Scoped Run
When modifying only specific models or providers, save substantial build time by targeting specific file filters:
```bash
# Generate only Freezed models
dart run build_runner build --build-filter="lib/models/**" --delete-conflicting-outputs

# Generate only Riverpod providers
dart run build_runner build --build-filter="lib/providers/**" --build-filter="lib/features/**/providers/**" --delete-conflicting-outputs

# Generate only Drift database & DAOs
dart run build_runner build --build-filter="lib/data/**" --build-filter="lib/core/database/**" --delete-conflicting-outputs
```

## 2. Optimized `build.yaml` Configuration

To prevent `build_runner` from scanning heavy asset folders (`assets/product_image/`, `assets/db/`, fonts) or test directories unnecessarily, configure targets in `build.yaml`:

```yaml
targets:
  $default:
    sources:
      - "lib/**"
      - "pubspec.yaml"
      - "$package$"
    builders:
      freezed:
        options:
          format: true
      json_serializable:
        options:
          explicit_to_json: true
          checked: true
          create_to_json: true
      drift_dev:
        options:
          apply_converters_on_custom_queries: true
          generate_connect_constructor: true
          generate_values_in_row_classes: true
```

## 3. Resolving Common Build Errors

### Error: Conflicting Outputs
**Symptom**: `Outputs were generated by a previous build and do not match current inputs.`
**Solution**:
```bash
dart run build_runner clean
dart run build_runner build --delete-conflicting-outputs
```

### Error: Missing `.freezed.dart` or `.g.dart` Part Directives
Ensure every file using code generation has exact matching `part` statements before running the builder:
- **Freezed + JSON**:
  ```dart
  import 'package:freezed_annotation/freezed_annotation.dart';

  part 'product.freezed.dart';
  part 'product.g.dart';
  ```
- **Riverpod**:
  ```dart
  import 'package:riverpod_annotation/riverpod_annotation.dart';

  part 'products_provider.g.dart';
  ```
- **Drift Database**:
  ```dart
  import 'package:drift/drift.dart';

  part 'app_database.g.dart';
  ```

### Error: Cache Corruption / Inconsistent AST
If `build_runner` fails mysteriously after branching, git rebasing, or updating dependencies:
```bash
flutter clean
flutter pub get
dart run build_runner clean
dart run build_runner build --delete-conflicting-outputs
```

## 4. CI/CD Code Generation Verification

To ensure generated code is never committed out-of-sync with source files, CI workflows run:
```bash
dart run build_runner build --delete-conflicting-outputs
git diff --exit-code
```
If `git diff` produces output, generated files were outdated before commit.
